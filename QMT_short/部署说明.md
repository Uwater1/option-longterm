# QMT 模拟盘部署说明（第一版草稿策略）

本文件夹包含第一个可执行的 QMT 期权模拟盘策略及其配套审计工具。
测试者**只需部署 `qmt_strategy.py` 一个文件到 QMT**，其余文件均在研究机（本仓库 venv）上运行。

---

## 1. 文件夹内容

| 文件 | 用途 | 在哪里运行 |
| --- | --- | --- |
| `qmt_strategy.py` | 策略本体：特征计算 + 信号 + 下单/止损/平仓全部在这一个文件里（仅依赖标准库 + numpy，无任何仓库内部依赖） | **QMT 客户端** |
| `qmt_audit_replay.py` | 收盘后审计脚本：用下载好的行情数据离线重算当日决策，产出与 QMT 端**完全相同格式**的 AUDIT 日志 | 研究机（仓库 venv） |
| `部署说明.md` | 本文档 | - |

## 2. 策略逻辑速览

- 标的：500ETF（510500）与 创业板ETF（159915）的**期权**，只买不卖（多头买 Call、看空买 Put）。
- 信号来源是**指数**（500ETF → 000905.SH；159915 → 399006.SZ）开盘后前 6 根 5 分钟 K 线（9:30–10:00）计算的 24 个原始特征 → 组合成每个 ETF 各 10 个入选特征 → z-score 标准化后按符号平均得 composite 综合分。
- 10:00 决策：`composite > z_th_long` 买 Call；`composite < -z_th_short` 买 Put；否则不动。
  - 500ETF 阈值：多 0.70 / 空 1.20；159915ETF 阈值：多 1.10 / 空 1.00。
  - **晚启动保护（ENTRY_CUTOFF = 10:05）**：如果决策直到 10:05 之后才发生（策略启动过晚 / 10:00 指数 K 线迟到），只打印与记录信号（控制台 + AUDIT DECISION + `SKIP REASON=late_entry`），**不下单**。正常 10:00:00–10:05:00 之间做出的决策照常下单（宽限窗口吸收 QMT 推送延迟；如需更严可把顶部常量 `ENTRY_CUTOFF` 改小）。
- 合约选择：当月（DTE 1–45 取最近月）；500ETF 选最平值行权价（nearest），159915 选盘口流动性最好的行权价（vol_t1 的近似）。
- 每次买 1 张，权利金上限 10,000 元；限价 = 卖一价 + 1 个最小变动价位。
- 持仓管理：期权价格时间衰减型移动止损（开盘允许从峰值回撤 30%，随时间收紧）；14:35 强制平仓；14:45 兜底清空。
- 每个 ETF 每天最多一次开仓；止损后当日不再开仓。
- 状态文件：脚本同目录 `qmt_state/state_YYYYMMDD.json`（崩溃恢复用；删除即可重置当日）。

## 3. 部署步骤（QMT 端）

1. 将 `qmt_strategy.py` 复制到 QMT 客户端的策略目录，作为**模型交易策略**加载。
2. 绑定**期权账户（STOCK_OPTION）**，选择**模拟交易**模式。
   - 脚本内烘焙配置中已写入账户号 `210889000248`；如 QMT 框架自动注入账户则无需改动，否则在文件顶部 `QMT_CONFIG` 的 `"account"` 字段修改。
3. 审计日志开关：文件顶部 `AUDIT_LOG_FILE`（置空字符串可关闭）。日志与 `qmt_state/` 目录默认写在**脚本所在目录**；若 QMT 以字符串方式加载脚本（无 `__file__`），则自动回退到 QMT 当前工作目录。**启动时 init 日志会直接打印两个绝对路径**（`audit log -> ...` 与 `state dir -> ...`），找不到文件时先看控制台这两行。
4. 启动后检查 init 日志，必须看到两行：
   - `[500ETF] chain built: N (expiry,strike) pairs`（N ≥ 10）
   - `[159915ETF] chain built: N (expiry,strike) pairs`
   - 若为 0：检查期权行情/交易权限。
5. 确认指数行情可用：策略通过 `get_market_data_ex` 拉取 000905.SH / 399006.SZ 的 5 分钟与日线数据。若日志出现 `skip: index bars unavailable`，说明指数数据订阅有问题。
6. 每个交易日 10:00 后应看到每个 ETF 各一行决策日志：`composite=... side=long|short|flat`。

预期活跃度：约 40–65 笔期权交易/年/ETF；信号日开仓比例约 55–66%。

## 4. 每日审计流程（重点）

目的：确认 QMT 端拿到的数据和执行路径与研究端完全一致。**与交易盈亏无关，纯粹校验一致性。**

### 4.1 QMT 端（自动）

策略运行中会自动把以下结构化行追加写入 `qmt_audit_log.txt`：

```
AUDIT <日期> DECISION <ETF> prev_close=... exp_bar_vol=... FEATURES=[24个原始特征值] ZSIGNED=[10个带符号z值] composite=... TH=long:.../short:... SIDE=long|short|flat TIME=HH:MM:SS
AUDIT <日期> ENTRY <ETF> CONTRACT=... SIDE=... ask=... order_price=... composite=... TIME=HH:MM:SS
AUDIT <日期> STOP|EXIT1435|DEADLINE <ETF> CONTRACT=... price=... TIME=HH:MM:SS
AUDIT <日期> SKIP <ETF> REASON=no_bars|bad_bars|no_contract|no_ask|cost_cap|late_entry TIME=HH:MM:SS
```

- **每行末尾的 `TIME=HH:MM:SS` 是该行写入的墙钟时刻**。重点监控 `DECISION` 行的 TIME：应尽量接近 `10:00:00`（正常为 10:00 后几秒内）。明显偏晚说明 10:00 时指数 K 线未就绪或策略启动过晚。
- **每个 ETF 每天只写一条 DECISION**：脚本会扫描当日已有审计行做去重，QMT 重启/重新加载也不会重复写。

每天收盘后，请把 QMT 机器上的 `qmt_audit_log.txt` 拷回研究机。

### 4.2 研究机端（收盘后）

1. 下载当日数据（指数 5 分钟 / 日线 / ETF / 期权）：
   ```
   python update_data.py
   python download_5m_data.py
   python download_1m_data.py
   python download_index_data.py
   ```
2. （可选，建议）重建特征底表，供 xcheck 交叉验证：
   ```
   python day-model/build_features.py
   ```
3. 运行审计重放（日期为刚收盘的交易日）：
   ```
   python QMT_short/qmt_audit_replay.py --date YYYYMMDD
   ```
   产出 `QMT_short/qmt_audit_replay_<date>.log`，其中 `AUDIT` 行与 QMT 端格式完全一致，另含 `REPLAY_XCHECK`（与特征底表比对，max_diff 应 ≤ 1e-4）与 `REPLAY_SIDE_REF` 参考行。

### 4.3 比对

先明确两类 AUDIT 行的预期：

| 行类型 | 预期 | 用途 |
| --- | --- | --- |
| `DECISION` / `SKIP` | **逐字节完全一致**（纯数据+纯计算，无执行环节） | 校验 QMT 数据源、配置、脚本三方一致性 |
| `ENTRY` / `STOP` / `EXIT1435` / `DEADLINE` | **不要求一致**：成交价取决于实时盘口与滑点，必然有差异 | 不是校验对象，而是**滑点观测数据**：`CONTRACT` 应一致；`price` 与研究端假设价的差就是当日真实滑点，记录下来用于评估执行质量 |

比对 DECISION/SKIP 行（REPLAY 开头的行只在研究机端出现，不参与比对）。
注意：`TIME=` 字段两边必然不同（QMT 端是 10:00 附近的实际决策时刻，重放是收盘后运行时刻），**比对前先去掉 TIME 字段**：

```
findstr AUDIT qmt_audit_log.txt | findstr "DECISION SKIP" | ForEach-Object { $_ -replace ' TIME=\d\d:\d\d:\d\d$','' } | Set-Content qmt_side.txt -Encoding UTF8
findstr AUDIT qmt_audit_replay_<date>.log | findstr "DECISION SKIP" | ForEach-Object { $_ -replace ' TIME=\d\d:\d\d:\d\d$','' } | Set-Content replay_side.txt -Encoding UTF8
fc qmt_side.txt replay_side.txt
```

`DECISION` 的 TIME 不参与比对，但 QMT 端的 TIME 本身是要检查的对象：应 ≈ `10:00:00`。

- **完全一致** → QMT 数据源、配置、脚本三方全部验证通过。
- **有差异** → 差异的字段名直接指出问题所在：

| 差异字段 | 含义 / 排查方向 |
| --- | --- |
| `FEATURES=[...]` 中某个特征 | QMT 取到的指数 5 分钟 K 线与仓库数据不一致（条数、时间戳对齐、数据源） |
| `prev_close` / `exp_bar_vol` | QMT 日线历史与仓库不一致，或 `_get_prev_context` 在 QMT 端回退到了 seed（看是否含 seed 值） |
| `ZSIGNED` 不同但 FEATURES 相同 | 烘焙配置不一致（QMT 端文件与 QMT_short 副本不是同一版本） |
| `composite` / `SIDE` 不同 | 阈值或符号配置被手改过 |
| QMT 有 `SKIP` 而重放没有 | QMT 端运行时事件：数据接口取数失败（`no_bars`/`bad_bars`，偶发）或决策晚于 10:05（`late_entry`，晚启动保护，属预期行为而非数据问题） |
| `ENTRY` 合约不同 | 期权链构建或行权价选择逻辑差异（对照 `get_option_list` 返回与仓库期权数据） |

注意：`ENTRY` 的价格差异属于正常滑点，不是 bug；只有 `CONTRACT` 不同才需要排查。把每天的成交价与 ask 假设价的偏差累计下来，就是该策略的真实执行成本样本。

已知可忽略的误差：`early_order_flow_imbalance` 等含大额成交量加减的特征允许 ≤ 2e-5 的浮点差（研究端 numba fastmath 重排所致），其余特征应完全一致。

## 5. 常见问题

- **QMT 报编码错误**：脚本为纯 ASCII 内容 + gbk 声明，正常不会触发；请勿用会引入中文注释的编辑器另存。
- **10:00 没有任何日志**：确认策略处于运行状态、当天是交易日、指数数据订阅正常。
- **想调整参数**：所有可调项集中在文件顶部常量与 `QMT_CONFIG` 块（权重、阈值、合约数、权利金上限、止损系数等）；修改后请重新走一遍第 4 节审计流程确认一致。
- **重置某一天**：删除 `qmt_state/state_<日期>.json` 并重启策略。
- **复现历史某天**：研究机上 `python QMT_short/qmt_audit_replay.py --date <历史日期>` 即可（QMT 端无法回测）。
